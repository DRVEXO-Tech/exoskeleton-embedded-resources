# 驭介智能科教外骨骼电机 FDCAN 通信协议

## **在此强调，只建议采用MIT模式做运动控制，电机最大力矩是15NM，请勿给出超过范围，最大转速是120rad/s。在给定MIT的参数时建议力矩从1.0f开始，kp和kd从0.1f开始，切记！！！MIT公式如下**

```text
torque_cmd = torque_ff
           + kp × (position_ref_turn - position_meas_turn)
           + kd × (velocity_ref_turn_s - velocity_meas_turn_s)
```

## 1. 通信参数

| 项目 | 参数 |
| --- | --- |
| 总线类型 | CAN FD，开启 BRS（Bit Rate Switch） |
| CAN 标识符 | 11 位标准帧 |
| 仲裁段速率 | 1 Mbps |
| 数据段速率 | 4 Mbps |
| 发送帧类型 | CAN FD 数据帧，BRS 开启 |
| 多字节整数 | 小端序，低字节在前 |
| 浮点数 | 32 位 IEEE 754 单精度，小端序 |
| 电机遥测周期 | 7 ms |
| 单帧最大数据长度 | 64 字节 |

总线上所有节点都必须支持 CAN FD+BRS。使用 USB-CAN 工具时，应分别配置仲裁段为 1 Mbps、数据段为 4 Mbps，并启用 ISO CAN FD 和 BRS。

CAN 总线两端各接一个 120 Ω 终端电阻。断电测量 CAN_H 与 CAN_L 之间的等效电阻，应约为 60 Ω。

## 2. CAN ID 分配

### 2.1 二次开发常用 ID

| CAN ID | 方向 | 长度 | 用途 |
| --- | --- | ---: | --- |
| `0x000` | 左电机 → 总线 | 48 | 左电机周期遥测 |
| `0x001` | 右电机 → 总线 | 48 | 右电机周期遥测 |
| `0x002` | 左电机 → 主控 | 1 或 4 | 左电机设置命令回复 |
| `0x003` | 右电机 → 主控 | 1 或 4 | 右电机设置命令回复 |
| `0x300` | 主控 → 左电机 | 5 或 24 | 左电机实时控制命令，不回复 |
| `0x301` | 主控 → 右电机 | 5 或 24 | 右电机实时控制命令，不回复 |
| `0x310` | 主控 → 左电机 | 1、2 或 20 | 左电机设置/维护命令 |
| `0x311` | 主控 → 右电机 | 1、2 或 20 | 右电机设置/维护命令 |

实时控制和普通设置必须使用对应的 ID。比如 `SET_TORQUE(3)` 应发到 `0x300/0x301`，而 `MOTOR_ENABLE(1)` 应发到 `0x310/0x311`。

### 2.2 系统内部及维护 ID

| CAN ID | 方向 | 长度 | 用途 |
| --- | --- | ---: | --- |
| `0x100 / 0x101` | 电机 → 电机 | 3 | 左/右电机按键与系统力矩同步 |
| `0x200 / 0x201` | 电机 → 电机 | 4 | 左/右电机同步回应 |
| `0x302` | 核心板 → 总线 | 4 | 核心板在线心跳，内容为毫秒时间戳 |
| `0x303` | 电池板 → 总线 | 48 | 电池周期数据 |
| `0x304 / 0x305` | 核心板 → 电机 | 1 或 64 | 左/右电机 OTA 通道及 APP 确认 |
| `0x400 / 0x401` | 电机 → 核心板 | 1 或 5 | 左/右电机 OTA 回复 |

左右电机通过编译期 `MOTOR_ID` 区分：左电机为 `0x000`，右电机为 `0x001`。当前协议不是运行时动态分配 ID，命令 `SET_MOTOR_STD_ID(30)` 在电机端未实现。

## 3. 数据与回复约定

所有命令帧的 `data[0]` 都是命令码，后续字节为该命令的参数。电机只在 DLC 与规定长度完全一致时执行命令；长度错误通常会被直接忽略，并且不回复。

### 3.1 普通回复

普通设置命令在 `0x002/0x003` 上返回 1 字节：

| 回复值 | 含义 |
| --- | --- |
| `0x00` | 命令执行成功 |
| `0xEE` | 命令执行失败 |

实时控制命令 `3、4、5、29` 不返回 ACK。固件版本命令 `28` 返回专用的 4 字节数据，不使用普通回复格式。

> 接收到 CAN 帧只说明链路正常；应用程序还应检查回复字节是否为 `0x00`。当前核心板的通用等待函数只等待回复到达，没有判断收到的是 `0x00` 还是 `0xEE`。

### 3.2 控制模式

命令 `SET_OP_MODE(0)` 的 `data[1]` 取值如下：

| 值 | 模式 | 后续实时命令 |
| ---: | --- | --- |
| `0` | 力矩斜坡 | `SET_TORQUE(3)` |
| `1` | 速度斜坡 | `SET_VELOCITY(4)` |
| `2` | 位置滤波 | `SET_POSITION(5)` |
| `3` | 位置轨迹 | `SET_POSITION(5)` |
| `4` | MIT 阻抗控制 | `SET_MIT_MODE(29)` |

模式设置帧为 `[0x00, mode]`，DLC=2，发到 `0x310/0x311`，通过 `0x002/0x003` 返回普通回复。

## 4. 基础控制命令

| 命令码 | 名称 | 发送 ID | DLC | `data[1...]` | 回复 |
| ---: | --- | --- | ---: | --- | --- |
| `0` | `SET_OP_MODE` | `0x310/0x311` | 2 | `uint8_t mode`，见控制模式表 | 1 字节 ACK |
| `1` | `MOTOR_ENABLE` | `0x310/0x311` | 1 | 无 | 1 字节 ACK |
| `2` | `MOTOR_DISABLE` | `0x310/0x311` | 1 | 无 | 1 字节 ACK |
| `3` | `SET_TORQUE` | `0x300/0x301` | 5 | `float torque`，单位 N·m | 无 |
| `4` | `SET_VELOCITY` | `0x300/0x301` | 5 | `float velocity`，单位 rad/s | 无 |
| `5` | `SET_POSITION` | `0x300/0x301` | 5 | `float position`，单位 rad | 无 |
| `6` | `SYNC` | `0x310/0x311` | 1 | 无 | **当前电机固件不回复** |
| `7` | `CALIB_START` | `0x310/0x311` | 1 | 无 | 1 字节 ACK |
| `13` | `SET_HOME` | `0x310/0x311` | 1 | 无 | 1 字节 ACK |
| `28` | `GET_FW_VERSION` | `0x310/0x311` | 1 | 无 | 4 字节版本信息 |
| `29` | `SET_MIT_MODE` | `0x300/0x301` | 24 | 5 个 `float`，见下文 | 无 |

### 4.1 使能和失能

- `MOTOR_ENABLE(1)`：请求进入 RUN 状态。电机未完成标定、存在故障或当前状态不允许切换时回复 `0xEE`。
- `MOTOR_DISABLE(2)`：停止标定任务并请求进入 IDLE 状态。正常停止、切换模式或调试结束时应优先发送该命令。
- 电机刚进入 RUN 时，控制器会将目标初始化为当前位置、当前速度和零力矩，避免使能瞬间产生阶跃。

### 4.2 力矩、速度和位置

这三个命令的帧格式相同：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| `0` | `uint8_t` | 命令码 `3/4/5` |
| `1～4` | `float` | 目标值，小端序 |

电机收到速度和位置后，会分别由 `rad/s`、`rad` 换算为内部使用的 `turn/s`、`turn`。若电机方向反转配置有效，电机固件会自动处理符号，上位机仍按外骨骼统一坐标方向发送。

当 `sync_target_enable=0` 时，目标在收到后立即生效；当 `sync_target_enable!=0` 时，命令 `3/4/5/29` 只更新缓存，随后发送 `SYNC(6)` 才统一提交。

### 4.3 MIT 阻抗控制

MIT 命令 DLC 固定为 24 字节：

| 偏移 | 类型 | 字段 | 单位 |
| ---: | --- | --- | --- |
| `0` | `uint8_t` | 命令码 `29` | — |
| `1～4` | `float` | 目标位置 `position` | rad |
| `5～8` | `float` | 目标速度 `velocity` | rad/s |
| `9～12` | `float` | 位置增益 `kp` | N·m/turn |
| `13～16` | `float` | 速度增益 `kd` | N·m/(turn/s) |
| `17～20` | `float` | 前馈力矩 `torque` | N·m |
| `21～23` | `uint8_t[3]` | 保留，填 `0x00` | — |

当前控制器内部按圈和圈每秒计算：

```text
torque_cmd = torque_ff
           + kp × (position_ref_turn - position_meas_turn)
           + kd × (velocity_ref_turn_s - velocity_meas_turn_s)
```

**因此，虽然位置和速度的线上单位是 `rad` 与 `rad/s`，当前 `kp/kd` 的实际量纲仍按内部的 `turn` 与 `turn/s` 解释。调参应从小值开始。**

### 4.4 固件版本

请求：命令 `28`，DLC=1。回复格式：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| `0` | `uint8_t` | 固定为命令码 `28`（`0x1C`） |
| `1` | `uint8_t` | 主版本号 |
| `2` | `uint8_t` | 次版本号 |
| `3` | `uint8_t` | 修订版本号 |

例如，保存于电机配置区的版本为 `0.1.5` 时，回复为 `1C 00 01 05`。实际回复以电机 Flash 中保存的版本为准。

## 5. 系统状态命令

以下命令属于外骨骼系统控制，也通过左右电机的设置 ID 发送：

| 命令码 | 名称 | DLC | 参数 | 当前行为 |
| ---: | --- | ---: | --- | --- |
| `31` | `SET_LOOSE_MODE` | 1 | 无 | 正常供电且未被充电锁定时进入脱机模式；回复 ACK |
| `32` | `SET_SYSPOWER` | 2 | `data[1]`：`0` 休眠，`1` 正常 | 更新系统电源状态；回复 ACK |
| `33` | `SET_SYSMODE` | 2 | `data[1]`：系统模式 | 更新系统模式；值 `1` 兼容映射为舒适模式 `0`；回复 ACK |
| `34` | `SET_SYSTORQUE` | 2 | `data[1]`：助力档位百分比 | 更新系统力矩；回复 ACK |
| `35` | `OTA_START_LIGHT` | 2 | `data[1]`：`0/1` | 控制 OTA 状态与灯效；维护使用 |
| `36` | `SET_BRIGHTNESS` | 2 | `data[1]`：`0～100` | 设置灯光亮度，超过 100 按 100 处理 |

系统模式编码：

| 值 | 模式 |
| ---: | --- |
| `0` | 舒适模式 |
| `2` | 运动模式 |
| `3` | 极限模式 |
| `4` | 阻尼模式 |
| `5` | 休息模式 |
| `13` | 脱机模式 |
| `14` | OTA 模式 |
| `15` | 驱动错误模式 |

系统力矩在产品按键逻辑中通常使用 `25、50、75、100` 四档。协议字段本身是 `uint8_t`，建议二次开发时限制在 `0～100`。

## 6. 电机周期遥测

左、右电机分别以 `0x000`、`0x001` 每 7 ms 主动发送一次 48 字节遥测。所有字段紧密排列，无结构体对齐填充：

| 偏移 | 长度 | 类型 | 字段 | 单位/说明 |
| ---: | ---: | --- | --- | --- |
| `0～1` | 2 | `uint16_t` | `fault_code` | 故障字低 16 位 |
| `2` | 1 | `uint8_t` | `button` | 高 4 位为电源状态，低 4 位为系统模式 |
| `3～4` | 2 | `uint16_t` | `sys_torque` | 系统助力档位，% |
| `5～8` | 4 | `float` | `input_angle` | 电机输入轴角度，rad |
| `9～12` | 4 | `float` | `output_angle` | 输出轴相对零位角度，rad |
| `13～16` | 4 | `float` | `torque` | 估算输出力矩，N·m |
| `17～20` | 4 | `float` | `current` | q 轴电流，A |
| `21～24` | 4 | `float` | `input_velocity` | 输入轴角速度，rad/s |
| `25～28` | 4 | `float` | `input_acceleration` | 输入轴角加速度，rad/s²；当前固件固定为 `0.0` |
| `29～32` | 4 | `float` | `output_velocity` | 输出轴角速度，rad/s |
| `33～36` | 4 | `float` | `output_acceleration` | 输出轴角加速度，rad/s² |
| `37～40` | 4 | `float` | `temperature` | 电机绕组温度，℃ |
| `41～47` | 7 | `uint8_t[7]` | 保留 | 当前填 `0x00`，接收端应忽略 |

`button` 字节解析方法：

```c
uint8_t power_state = (uint8_t)(button >> 4);   // 0=休眠，1=正常
uint8_t system_mode = (uint8_t)(button & 0x0F); // 见系统模式编码
```

### 6.1 故障码

当前遥测仅发送内部 32 位错误字的低 16 位：

| 位 | 掩码 | 含义 |
| ---: | ---: | --- |
| `0` | `0x0001` | ADC 自检致命错误 |
| `1` | `0x0002` | 编码器离线；当前检测代码未启用 |
| `2～15` | — | 保留 |

内部过压、欠压、过流和过温分别位于错误字 bit16～bit21，因 `fault_code` 被转换为 `uint16_t`，当前 48 字节遥测无法上报这些位。不能仅凭 `fault_code==0` 判断所有内部保护均正常。

## 7. C 语言打包示例

以下定义与当前固件的线上布局一致。编译器必须支持 32 位 IEEE 754 `float`。

```c
#include <stdint.h>

#pragma pack(push, 1)

/* 力矩、速度或位置实时命令，修改cmd和value即可。 */
typedef union
{
    struct
    {
        uint8_t cmd;
        float value;
    } data;
    uint8_t buf[5];
} MotorFloatCmd_u;

/* MIT实时控制命令，保留字节必须清零。 */
typedef union
{
    struct
    {
        uint8_t cmd;
        float position;
        float velocity;
        float kp;
        float kd;
        float torque;
        uint8_t reserved[3];
    } data;
    uint8_t buf[24];
} MotorMitCmd_u;

/* 左右电机通用的48字节周期遥测。 */
typedef union
{
    struct
    {
        uint16_t fault_code;
        uint8_t button;
        uint16_t sys_torque;
        float input_angle;
        float output_angle;
        float torque;
        float current;
        float input_velocity;
        float input_acceleration;
        float output_velocity;
        float output_acceleration;
        float temperature;
        uint8_t reserved[7];
    } data;
    uint8_t buf[48];
} MotorTelemetry_u;

#pragma pack(pop)
```

发送前应将整个联合体清零，再填写字段，防止 MIT 保留字节携带随机数据。若接收端 CPU 不支持非对齐访问，应先把字节复制到对齐变量，再读取 `float`。

## 8. 典型报文

以下数据均按十六进制列出。

### 8.1 左电机力矩模式，目标 1.0 N·m

```text
发送 ID 0x310，DLC 2：00 00             # 设置力矩模式
接收 ID 0x002，DLC 1：00                # 成功

发送 ID 0x310，DLC 1：01                # 使能电机
接收 ID 0x002，DLC 1：00                # 成功

发送 ID 0x300，DLC 5：03 00 00 80 3F    # float 1.0 N·m，无回复
```

### 8.2 右电机位置模式，目标 1.0 rad

```text
发送 ID 0x311，DLC 2：00 02             # 设置位置滤波模式
接收 ID 0x003，DLC 1：00

发送 ID 0x311，DLC 1：01                # 使能
接收 ID 0x003，DLC 1：00

发送 ID 0x301，DLC 5：05 00 00 80 3F    # 位置 1.0 rad，无回复
```

### 8.3 左电机 MIT 控制

目标位置 1.0 rad、目标速度 0、`kp=1.0`、`kd=0.1`、前馈力矩 0：

```text
发送 ID 0x310，DLC 2：00 04
接收 ID 0x002，DLC 1：00

发送 ID 0x310，DLC 1：01
接收 ID 0x002，DLC 1：00

发送 ID 0x300，DLC 24：
1D
00 00 80 3F
00 00 00 00
00 00 80 3F
CD CC CC 3D
00 00 00 00
00 00 00
```

### 8.4 读取右电机固件版本

```text
发送 ID 0x311，DLC 1：1C
接收 ID 0x003，DLC 4：1C 00 01 05       # 示例版本 0.1.5
```

## 9. 推荐控制流程

1. 配置 CAN FD：仲裁段 1 Mbps、数据段 4 Mbps、BRS 开启。
2. 等待收到对应电机的 `0x000/0x001` 48 字节遥测，确认总线和电机在线。
3. 向 `0x310/0x311` 发送 `MOTOR_DISABLE(2)`，收到 `0x00` 后再配置模式。
4. 发送 `SET_OP_MODE(0)` 并检查 ACK。
5. 发送 `MOTOR_ENABLE(1)`，只有收到 `0x00` 才开始控制。
6. 以小目标、小增益开始发送实时命令，逐步增加；同时持续监测遥测周期、温度、电流和力矩。
7. 通信超时、收到失败回复、遥测中断或操作结束时，发送 `MOTOR_DISABLE(2)`。

MIT 模式下，电机使能时会把目标位置和速度对齐到测量值。使能成功后再逐步发送 MIT 参数，可减小力矩突变。

这些命令用于生产、校准或升级，不建议普通二次开发流程直接调用。

| 命令码 | 名称 | DLC | 参数/回复 |
| ---: | --- | ---: | --- |
| `35` | `OTA_START_LIGHT` | 2 | `data[1]=0/1`，普通 ACK |
| `36` | `SET_BRIGHTNESS` | 2 | 亮度 `0～100`，普通 ACK |
| `37` | `MOTOR_OTA_START` | 20 | 版本、长度、包数、CRC32；普通 ACK |
| `38` | `FAN_TEST` | 2 | `data[1]=0/1`，普通 ACK |
| `39` | `KEY_RGB_TEST` | 2 | `data[1]=0/1`，普通 ACK |
| `40` | `MOTOR_CALIB_STATUS` | 1 | 返回 1 字节标定状态，不一定是标准 `0x00/0xEE` |
| `41` | `MOTOR_DISABLE_DISCONNECTION_ALARM` | 1 | 关闭断连告警，普通 ACK |
| `42` | `CALIB_START2` | 1 | 启动第二标定流程，普通 ACK |
| `43` | `CORE_ERROR_STATUS` | 2 | `data[1]` bit0～bit4 为核心板错误状态，普通 ACK |
| `44` | `ALGORITHM_CALIB_LIGHT` | 1 | 启动算法标定灯效，普通 ACK |

## 11. 当前实现限制

1. 电机端当前未实现命令 `8～12`、`14～18`、`23～27` 和 `30`。其中部分命令在核心板仍保留同名 API，但发送后不会获得有效响应。
2. `SYNC(6)` 会执行同步提交，但电机端没有发送 ACK；核心板 `APP_Control_Sync()` 当前按等待 ACK 实现，因此会超时。直接使用 CAN 时，发送后不要等待回复。
3. 实时命令 `3、4、5、29` 设计为无回复，发送端应依靠周期遥测和通信超时策略判断运行状态。
4. 核心板的普通设置等待逻辑只在收到 `0x002/0x003` 后结束等待，没有判断回复字节是 `0x00` 还是 `0xEE`。二次开发代码应自行校验回复值。
5. `fault_code` 只包含内部错误字的低 16 位，过压、欠压、过流和过温等高位错误当前不会出现在遥测故障码中。
6. 遥测中的输入轴角加速度当前固定为 `0.0`；输出轴数据依赖输出编码器是否正常采样。
7. 当前协议使用固定左右电机 ID。不要依赖未实现的命令 `SET_MOTOR_STD_ID(30)` 修改节点 ID。
8. 电机在控制环就绪前会丢弃提前到达的控制帧；应先等待周期遥测，再发送设置和控制命令。

---

本文所有角度量统一使用弧度制：角度为 `rad`，角速度为 `rad/s`，角加速度为 `rad/s²`。
